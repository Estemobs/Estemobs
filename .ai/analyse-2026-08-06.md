## Résumé

Le dépôt `estemobs/Estemobs` est un « profil README » GitHub plus qu’un projet applicatif. Il contient une page de présentation, une clé PGP publique et un workflow GitHub Actions `check-widgets.yml` destiné à vérifier les widgets affichés. L’ensemble est simple et maintenable, mais quelques points de robustesse, de liens et de vérification automatique sont à corriger.

## Problèmes et bugs potentiels

- `README.md` : le lien `https://discord.chat/domainedecasinus` n’est pas un domaine officiel de Discord. Il faut utiliser une invitation officielle du type `https://discord.gg/...` ou `https://discord.com/invite/...`.
- `README.md` : les badges `Andorra-📍-` et `Linux-🐧-` utilisent des emojis bruts dans l’URL. Cela peut casser certains parseurs Markdown ou validateurs HTML. Il est préférable d’encoder ces emojis en pourcent.
- `README.md` : le lien vers `ESTEMOBS_public.asc` est relatif. En affichage de profil GitHub, ce type de lien est ambigu et peut être résolu par rapport à l’URL du profil et non du dépôt. Utiliser une URL absolue : `https://github.com/Estemobs/Estemobs/raw/main/ESTEMOBS_public.asc`.
- `.github/workflows/check-widgets.yml` : le workflow ne couvre probablement que les widgets, pas tous les liens du README. Les liens Discord, PGP et les ancres internes devraient aussi être vérifiés.
- `.github/workflows/check-widgets.yml` : un simple contrôle HTTP 200 ne garantit pas qu’un widget est valide. Vérifier, si possible, le `Content-Type` de la réponse pour s’assurer qu’il s’agit bien d’une image.

## Qualité du code et nettoyage

- `README.md` : les badges utilisent un mélange de HTML brut et de Markdown. Pour plus de cohérence, utiliser systématiquement la syntaxe Markdown `[![alt](URL_image)](URL_cible)`.
- `README.md` : plusieurs images n’ont pas d’attribut `alt` : badges `Profile views`, `Discord`, `PGP`, `Andorra`, `Linux`. Seuls `GitHub Stats` et `Top Languages` en ont. Des `alt` descriptifs amélioreraient l’accessibilité.
- `README.md` : la clé PGP est présentée uniquement via un identifiant court `0xCEA97C9C`. Ajouter l’empreinte complète de la clé pour permettre une vérification réelle.
- `.github/workflows/check-widgets.yml` : si le workflow contient un script shell, le linter avec `shellcheck` ou `actionlint` pour éviter les erreurs silencieuses.

## Nouvelles fonctionnalités à envisager

- `README.md` : ajouter une section « Projets » listant les dépôts principaux du profil avec une courte description.
- `README.md` : ajouter une section « Contact » claire incluant Discord, PGP et éventuellement un email signé.
- `.github/workflows/check-widgets.yml` : remplacer le script maison par `lycheeverse/lychee-action` pour vérifier tous les liens du README en une seule commande.
- `README.md` : ajouter un badge ou une mention indiquant les technologies réellement utilisées (Bash, Python, bots Discord, etc.) pour enrichir le profil.
- Ajouter un déclencheur `schedule` au workflow pour vérifier périodiquement les widgets et liens, même sans nouveau `push`.

## Tests manquants

- Il n’y a pas de code applicatif, donc pas de tests unitaires pertinents.
- Le workflow `check-widgets.yml` ne teste pas l’intégralité du README : il manque une vérification de `ESTEMOBS_public.asc`, de `LICENSE`, des liens Discord et des ancres internes.
- Le workflow lui-même n’est pas linté. Une étape `actionlint` permettrait de valider sa syntaxe et ses bonnes pratiques.

## Dépendances et sécurité

- `README.md` dépend de services tiers : `komarev.com`, `shields.io`, `ghstats.dev`, `discord.com`, `discord.chat`. Leur indisponibilité peut casser l’affichage du profil.
- Aucun gestionnaire de paquets ni fichier de dépendances n’est présent : pas de vulnérabilité connue côté dépendances.
- Si le workflow utilise des actions GitHub, vérifier qu’elles sont épinglées à un SHA complet et non à une simple étiquette `@v4` ou `@v1`, afin de limiter les risques de supply chain.
- `ESTEMOBS_public.asc` : vérifier que la clé PGP n’est ni expirée, ni révoquée, et que l’identifiant affiché correspond bien à l’empreinte réelle de la clé.
